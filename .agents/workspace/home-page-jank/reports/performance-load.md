# Performance Audit Report: Home Page First-Load Jank (home-page-jank)

Scope: initial load / first paint / first scroll path only. Read-only review; no source file was modified.

## 1. Executive Summary
- **Overall Verdict**: FAIL (BLOCKED) — 2 Critical + 5 High findings.
- **Frame Budget Status**: Target 60 FPS (<= 16.6 ms/frame). Code comments claim "90Hz-safe" (11.1 ms) — not achievable with the current first-load path.
- **Max Severity Detected**: Critical
- **Measured build footprint (real)**: initial critical path = **544.40 kB raw / 162.02 kB gzip** (JS+CSS). Plus **156.78 kB raw / 46.88 kB gzip** of below-fold chunks that are *fetched and executed at first render* despite being "lazy".
- Root cause chain, in order: (1) a full-viewport `<canvas>` re-rasterizes 3 radial gradients over 8.29 M px at DPR 2 on a rAF loop and then re-blits a 33 MB bitmap every 50 ms, duplicating the CSS `.premium-mesh` gradient that is *already* painted underneath; (2) the hero LCP text starts at `opacity: 0` and is split into 10 `motion.span` layers, so nothing is eligible for LCP for ~0.55–1.15 s and the compositor thrashes ~16 layer promotions; (3) six `backdrop-filter` panels above the fold must re-blur *the live canvas* every 50 ms; (4) all six "lazy" sections download + parse + mount during the entrance animation; (5) `next-themes` applies the theme class in an effect, flipping the whole viewport's colors *after* first paint and forcing a second full-screen mesh raster.
- Fix order that removes the most jank per hour: PERF-01 → PERF-02 → PERF-03 → PERF-04 → PERF-05 → PERF-06 → PERF-07.

## 2. Static & Architectural Performance Checks
| Area | Check Performed | Status | Findings |
| :--- | :--- | :--- | :--- |
| **Re-render Isolation** | Component-level render scope; context consumers | FAIL | `useIsMobile()` is instantiated 7× inside Hero (1 `StaggerReveal` + 6 `Magnetic`); each owns a `matchMedia` + listener. Correct value arrives only on the 2nd render → variant swap mid-animation (PERF-09) |
| **Virtualized Lists** | Long lists use virtualization (`SliverList` → `ListVirtualized`) | PASS | No lists above the fold; below-fold grids are short static CSS grids. Nothing to virtualize |
| **Const / Static Discipline** | Static subtrees hoisted, stable object identities | FAIL | `containerVariants` and per-span `style={{...}}` objects recreated every render in `StaggerReveal.tsx:49-83`; `heroElementFadeUp` identity is stable but `Magnetic`'s `whileHover`/`interactive` recomputed per render |
| **Subscriptions / Dispose** | rAF, observers, listeners torn down | PASS (with bug) | All add/remove pairs are balanced. But the rAF chain self-terminates and can never restart (PERF-08) |
| **Main-thread Offload** | No heavy synchronous work on the UI thread | FAIL | Full-screen gradient raster + 33 MB canvas allocation happens synchronously inside the first rAF callback (PERF-01); full-document `querySelector` every frame (PERF-15) |
| **Image Constraints** | Explicit width/height, correct sizing, eager LCP image | PASS | `Hero.tsx:229-238` has `width/height`, `srcSet`, `fetchPriority="high"`, `loading="eager"`; `index.html:30-38` preloads it. LCP image itself is fine — it is hidden by animation, not by sizing |
| **CSS Paint Budget** | `blur-*` / `backdrop-*` / large shadows limited above the fold | FAIL | 2× `blur-[120px]`, 1× `blur-3xl`, `shadow-2xl`, 6× `backdrop-blur` in the hero + navbar (PERF-03, PERF-11) |
| **Composite Layers** | Layer count/promotions during entrance | FAIL | Canvas (opacity .55) + 10 animated spans + 6 animated wrappers + 6 backdrop layers ≈ 20+ layers created and destroyed in the first 2 s (PERF-02, PERF-03) |
| **Bundle Budget** | Initial chunk contains only above-fold code | FAIL | 42.41 kB radix chunk (dialog/tabs) preloaded into the critical path because it also carries `cn`; `sonner` (~toast) is inside the entry chunk (PERF-12) |
| **Font Loading** | Render-safe font strategy; no reflow during entrance | FAIL | `media="print"` swap defers the `@font-face` fetch past `load`; the swap reflows the split `<h1>` mid-stagger (PERF-06) |
| **Blocking Non-critical Work** | Analytics/tracking deferred past first paint | FAIL | `/api/track-visit` POST + UA parsing runs in the mount effect with `keepalive` (PERF-16) |

## 4. Performance Findings & Remediation Plan (ranked by first-load impact)
| ID | Severity | File | Line | Why it drops frames | Required Fix |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `PERF-01` | **Critical** | `src/components/animations/AnimatedBackground.tsx` | 50-71, 170-179, 275-280 | One synchronous long task in the very first rAF: allocate 2× 33 MB canvases, then 3 full-viewport `createRadialGradient`+`fillRect` over 8.29 M px — while the hero entrance runs. Afterwards `clearRect`+`drawImage` copies the whole 4K bitmap every 50 ms (≈20 full-screen composites/s, forever, even idle). Duplicates the gradient `.premium-mesh::before` already paints. | Delete the canvas mesh entirely — CSS already draws it. Keep only the 5 code snippets, as compositor-only DOM: `{SNIPPETS.map(s => <span aria-hidden className="absolute animate-snippet" style={{left: s.x+'%'}}>{s.text}</span>)}` + `@keyframes snippet{to{transform:translate3d(0,-100vh,0)}}`. If the canvas stays: `const dpr = 1` for the mesh layer, paint the gradients **once** into the main canvas at mount, remove `meshRef`/`drawImage`/`renderMesh` from the loop and drop the `opacity:0.55` style. |
| `PERF-02` | **Critical** | `src/components/Hero.tsx` / `src/components/animations/StaggerReveal.tsx` | 71-99 / 64-85 | `initial="hidden"` puts the whole hero at `opacity:0`, so the LCP element is *not eligible* until it paints opaque: 0.10 delay + own 0.10 delay + 9×0.06 word stagger + 0.45 duration ≈ **1.15 s** before the full `<h1>` is visible. Splitting the h1 into **10 inline-block `motion.span`s** promotes ~10 compositor layers that must be created, resized and destroyed, on top of 6 wrapper layers — layer churn is the classic cause of "smooth animation, dropped frames". | Reveal with transform only, never opacity, above the fold: `heroElementFadeUp.hidden = { y: 16 }`, `heroWordReveal.hidden = { y: "0.25em" }`, and drop the word split for the h1 (`<StaggerReveal mode="word">` → a single `motion.h1` with `variants={heroElementFadeUp}`). Text paints opaque on frame 1 (LCP recorded immediately), motion stays on the compositor. |
| `PERF-03` | **High** | `src/components/Hero.tsx` (+ `Navbar.tsx`) | 221, 246, 260, 274, 284 (Nav 100-101) | Six `backdrop-filter` regions sit above the live canvas. A backdrop-filter must re-snapshot and re-blur its backdrop whenever the backdrop changes — the canvas repaints every 50 ms, so 6 Gaussian blurs over ~90×60 px each are recomputed 20×/s for the entire session. `bg-background/90` is already 90 % opaque, so the blur is **visually invisible** and pure cost. | Delete the blur, keep the fill: `backdrop-blur-md bg-background/90` → `bg-background` (246, 260, 274, 284); drop `backdrop-blur-sm` from the photo ring (221). Navbar: use a permanent `bg-background/95` with no `backdrop-blur` (100), never toggle `backdrop-blur-none ↔ backdrop-blur-md`. |
| `PERF-04` | **High** | `src/pages/Index.tsx` | 15-25, 67-84 | `React.lazy` fires `import()` as soon as the element renders, and all six `BelowFold` wrappers render at mount → **156.78 kB raw / 46.88 kB gzip** (incl. `forms` 77.50 kB / 21.07 kB) is downloaded, parsed and *mounted* (dozens of `whileInView` observers + `initial="hidden"` nodes) during the hero animation. The comment "deferred chunks" is only true for the bundle graph, not for runtime. | Mount on approach, keep the CLS placeholder: `<div ref={ref} style={{minHeight}}>{show && <Suspense fallback={null}>{children}</Suspense>}</div>` with `new IntersectionObserver(([e]) => e.isIntersecting && (setShow(true), io.disconnect()), { rootMargin: "600px 0px" })`. |
| `PERF-05` | **High** | `index.html` / `src/App.tsx` / `src/components/theme-provider.tsx` | 55-58 / 53 / 6-12 | No pre-hydration theme script exists and `next-themes` applies `class` inside an effect (verified in `node_modules/next-themes/dist/index.mjs`: 3× `useEffect`, no injected script). Dark-mode visitors get: first paint light → full-viewport color repaint + `color-scheme` change + `MutationObserver` invalidating the mesh (AnimatedBackground:114-121) → a **second** full-screen gradient raster, all while the entrance animation is running. | Inline script before the module script: `<script>try{var t=localStorage.getItem('theme')||'system';var d=t==='dark'||(t==='system'&&matchMedia('(prefers-color-scheme: dark)').matches);document.documentElement.classList.toggle('dark',d);document.documentElement.style.colorScheme=d?'dark':'light'}catch(e){}</script>`. Then remove the now-pointless `MutationObserver` (see PERF-01). |
| `PERF-06` | **High** | `index.html` | 13-23 | `media="print" onload="this.media='all'"` makes the font CSS non-render-blocking *and* late: the `@font-face` request only starts after `load`, so Plus Jakarta Sans lands ~1 s in, `display=swap` reflows the `text-6xl/7xl` `<h1>` (different metrics than the fallback), and that reflow hits exactly while the 10 word-spans are mid-stagger → a visible hitch in the first second. 5 weights are requested although the hero uses 400/600/800. | One render-blocking link, 3 weights, self-hosted: `<link rel="stylesheet" href="/fonts/plus-jakarta.css">` (+ `@font-face{font-family:'Plus Jakarta Sans';src:url(/fonts/pjs-800.woff2)format('woff2');font-weight:800;font-display:swap;size-adjust:100.5%}`) and `<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/pjs-800.woff2">`. Delete the duplicate preload/`noscript` links. |
| `PERF-07` | **High** | `src/components/Navbar.tsx` | 98 | On the first scroll past 40 px the nav transitions `padding` — a **layout property** — for 500 ms (≈30 frames of layout+paint of the pill), together with `box-shadow` (paint) and a `backdrop-blur-none → backdrop-blur-md` swap (layer creation), on a `fixed` element above the animating canvas. This is the "dropped frames on first scroll" symptom. | `transition-[padding,background-color,border-color,box-shadow] duration-500` → `transition-colors duration-200`; make `py-5 → py-3` instant, or animate `transform: scaleY()` on a pseudo-element. | `PERF-08` | Medium | `src/components/animations/AnimatedBackground.tsx` | 152, 230-256 | `if (!isAnimatingRef.current) return;` exits **without** `requestAnimationFrame(draw)`. Result: the background freezes after the first scroll (correctness bug) and the "pause while scrolling" optimisation can never resume. | `if (!isAnimatingRef.current) { rafId = requestAnimationFrame(draw); return; }` and add `const kick = () => { cancelAnimationFrame(rafId); lastFrameTimeRef.current = 0; rafId = requestAnimationFrame(draw); }` called from both timeouts/handlers. | `PERF-09` | Medium | `src/hooks/use-mobile.tsx` / `StaggerReveal.tsx` | 6-14 / 49-60 | `useState<boolean|undefined>(undefined)` returns `!!undefined = false` on the first render, so mobile first paints with the **desktop** stagger (0.08 / 0.15) and then swaps to 0.05 / 0.10 in an effect — `containerVariants` is a new object, so framer-motion re-resolves and restarts the 10 span animations → mid-flight jump on mobile load. Hero creates 7 independent instances (7 `matchMedia` + 7 listeners). | Read the media query during the first render: `const isMobile = React.useSyncExternalStore(subscribe, () => window.innerWidth < 768, () => false)` — no `undefined` pass, one shared store, correct variants on frame 1. |
| `PERF-10` | Medium | `src/components/animations/Magnetic.tsx` / `HoverCard.tsx` | 32 / 15-18 | `hasFinePointer()` is called **during render**, so 6 `Magnetic`s + `HoverCard` issue 6–7 `window.matchMedia(...)` queries per render pass; media-query evaluation can invalidate style for pending mutations and repeats on every re-render (which PERF-09 guarantees). | Cache at module scope: `let fine: boolean|undefined; const hasFinePointer = () => (fine ??= matchMedia("(hover: hover) and (pointer: fine)").matches);` and read it in an effect/`useSyncExternalStore` instead of the render body. |
| `PERF-11` | Medium | `src/components/Hero.tsx` | 65, 66, 217, 221 | `blur-[120px]` on two 40 vh orbs and `blur-3xl` on a 288 px glow require large intermediate surfaces and a real Gaussian pass at first paint (one-time, but inside the paint that carries the LCP), plus `shadow-2xl` (50 px blur) on the photo frame. | `PERF-13` | Low | `src/components/Hero.tsx` | 83 | `animate-ping` (infinite `scale(1→2)` + `opacity 1→0`) keeps the page permanently "animating": the compositor never idles, so the first load never reaches a calm state and low-end devices burn CPU while the user reads. | Drop the ping span, or gate it: `className="motion-safe:animate-ping ... motion-reduce:hidden"` inside a `prefers-reduced-motion:no-preference` guard, and cap it with `animation-iteration-count: 3`. |
| `PERF-14` | Low | `src/hooks/use-scrollspy.ts` / `Navbar.tsx` | 8-28 / 122-128 | The observer is created once, when only `#home` is in the DOM (all other ids live in not-yet-mounted lazy chunks), and the effect never re-runs (`ids`/`rootMargin` stable) → `activeId` is permanently `"home"`, so the nav indicator never appears. ## 5. Notes / Unverified
- `framer-motion` (~128.91 kB / 42.52 kB gz) is genuinely needed above the fold by `Hero`/`Navbar`; replacing `motion.*` with `m` + `<LazyMotion features={domAnimation}>` would cut roughly half of it — worth doing *after* PERF-01..07, and it needs a measurement pass to confirm.
- Rewriting the hero grid's `initial`/`animate` still leaves one `motion.div` per wrapper (6 layers): acceptable once PERF-02's opacity gate is removed, because transform-only animations do not paint.
- Nothing was measured for LCP/CLS/FPS; a Chrome trace on a throttled profile (4× CPU, Fast 3G) is required to close PERF-01/02/03/05/06 with numbers instead of pixel math.
